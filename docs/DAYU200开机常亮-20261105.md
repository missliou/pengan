# DAYU200开机常亮与性能模式

任务：DAYU-BOOT-POWER-20261105。用户已明确答复“允许 root/su 一次性开机服务”，本次基于该新增授权实施。此前自动审批拒绝的方案没有在授权前部署。

## 部署内容

- 设备本次实读系统：OpenHarmony-7.1.0.22。
- tools/dayu200-power-boot.cfg → 板端 /system/etc/init/pengan-power.cfg。
- tools/dayu200-power-boot.sh → 板端 /system/etc/pengan-power.sh。
- 文件均root所有、0644；系统分区恢复只读。未修改原厂init配置或替换系统镜像。
- 独立服务pengan_power_boot：root用户、现有su调试域、POWER_MANAGER权限、ondemand:true、once:1。由bootevent.boot.completed=true触发，完成后退出，没有常驻循环或周期提权任务。
- 脚本调用系统官方power-shell：600（普通）→602（性能）→wakeup。先切普通是为重新应用性能模式的屏幕策略；已选602时仅再次设置602不会恢复被覆盖的超时。
- 本镜像602的策略将屏幕超时和自动睡眠设为-1，并应用SocPerf性能策略；也会采用镜像规定的亮度等设置。未超频、未关闭温控、未强制GPU最高频率。
- SELinux保持Enforcing；现有su调试域只用于本用户明确授权的短时开机任务，不是新建SELinux域或关闭全局策略。该配置针对当前开发镜像，不能当作生产设备的通用安全配置。

## 实际验证

1. 首次安装使用disabled字段，实际发现镜像不按该字段阻止早期启动，运行了两次；随后改成系统现有配置采用的ondemand:true。
2. 修改后再次真实重启，启动完成参数true；dmesg仅有一条ServiceStart starting:pengan_power_boot，随后exit with code:0。服务状态5为本次观察值，退出成功以日志证据为准。
3. 重启后读取AWAKE、Timeout=-1ms、CPU governor=performance、scaling_cur_freq=1800000kHz。
4. getenforce=Enforcing，根系统分区挂载ro。未进行软件安装、HSP烧录或修改后台配置。
5. 板端文件哈希与工程文件核对：cfg c4831042e438b00835f525f95aa0e6cd0fe9d3d7c4bd0677f4fb844a2d005c04；sh 0062d229c789be937766d8584933aff17ab7520e064906e1341cd0d45c512a76。
6. 最终开机111.59秒复查，Last Screen On=33015ms、Last Refresh=0、Last Screen Off=0，距服务唤醒约78秒仍AWAKE/Timeout=-1ms，超过原30秒熄屏窗口。证据tmp/verification/dayu-power-boot-20261105.txt。

当前验证覆盖软件重启，不包括人工拔电重上电或重新刷机。该系统分区配置正常重启会保留；刷机、系统升级替换分区或人工更改策略后须重新核验。用户手动切换省电模式也可改变本次开机后的策略。

## 回退（仅在需要时人工执行）

通过HDC进入该开发板shell，依次执行：

```sh
mount -o remount,rw /
mv /system/etc/init/pengan-power.cfg /system/etc/pengan-power.rollback.cfg
sync
mount -o remount,ro /
power-shell setmode 600
reboot
```

执行前确认回退目标文件不存在，避免覆盖旧备份；如已有同名备份，先选新的备份文件名。脚本不在init目录，保留它本身不会自动运行。原先失败的配置仍在/system/etc/pengan-power.disabled.cfg供追溯。本次没有实际执行回退。

重新启用需要将本轮cfg放回init目录并重启；如镜像变更，先核对官方模式编号、su域和启动事件，不能直接套用。
