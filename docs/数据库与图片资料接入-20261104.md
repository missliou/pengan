# 数据库与图片资料接入（2026-11-04）

## 当前选型

单实例采用SQLite（WAL + synchronous=FULL）保存结构化历史与图片索引；照片存放在服务端私有文件目录，鉴权接口逐次返回图片，不通过公开静态目录暴露。Node.js最低22.13，本机22.23.2已验证；此版本node:sqlite仍提示experimental。

依据：https://sqlite.org/whentouse.html 。当前单台Windows测试/单台Ubuntu服务与本地磁盘符合SQLite使用场景；多服务实例/更高写并发时改用PostgreSQL与对象存储，当前未实现PostgreSQL/S3适配，不能称为可直接切换。

## 数据与迁移

- `<dataDir>/database/records.sqlite`：history_records存telemetry/analysis/audit索引及完整JSON回执，media存图片元数据。
- `<dataDir>/database/images/<随机UUID>`：JPEG/PNG文件，名称不使用用户文件名。
- 原history.jsonl保留为原始审计链；启动校验原链后将缺失行事务导入SQLite，已存在行hash不一致时拒绝启动。新增历史先持久化原链再写SQLite，若中断，重启或重试可补齐索引。未删除/覆盖历史文件。
- 对外采集/AI历史查询已使用SQLite设备+类型+序号索引；原有任务/审核/告警的重放仍沿用保留审计链。
- 当前原链默认64MiB容量保护仍在，不是无限量历史存储。图片总量上限5000张/512MiB，单张2MiB。达到上限拒绝新增，不删除旧资料。
- media字段：设备、作物/人员类别、说明、实际拍摄时间、保存时间、登记人、可选本设备telemetry序号、SHA256、字节数、MIME及尺寸。

## 接口（新增，不改变原生现有请求字段）

| 接口 | 权限/用途 |
|---|---|
| GET /admin-api/storage | admin：数据库与图片数量/容量 |
| GET /admin-api/media?gatewayId=...&category=crop或person&limit=20&beforeSeq=... | admin看全部；viewer仅作物；设备隔离/游标分页 |
| POST /admin-api/media?gatewayId=... | admin+Origin+CSRF；保存图片 |
| GET /admin-api/media/{mediaId}?gatewayId=... | 可见元数据；不可见人员/跨设备返回404 |
| GET /admin-api/media/{mediaId}/content?gatewayId=... | 会话鉴权、完整性校验、no-store；登记浏览审计 |
| POST /api/v1/device/media | 设备Bearer+x-pengan-gateway-id认证；仅保存该设备图片 |

上传JSON：category为crop/person，label为1–120字说明，capturedAt为实际拍摄毫秒时间，telemetrySeq可为空（有值须属本设备真实采集记录），authorized必须为true，base64为纯图片base64（不含data URL头）。仅JPEG/PNG，不接收SVG/HTML；校验编码、文件头/尺寸、字节数，不能替代完整媒体解码或内容检测。尺寸最大8192边长、2400万像素。

保存、浏览具备审计记录；base64不写日志或审计链。图片只有SQL元数据提交后可见；中断可能留下未索引文件，未自动清理或删除。上传响应丢失时界面提示先刷新核对，不自动重试；本版尚无上传幂等键。

人员图片仅admin可见；设备上传主体只准写入自己的设备。上传需人工确认有权保存；没有人脸识别、人员身份判定或人脸模板。图片不自动发送给模型、不自动加入RAG。当前没有自动EXIF清除、静态加密、人员图片保留期限/删除UI；上线前根据实际用途补齐这些策略，不能把SHA256完整性校验称为加密。

## 启动与使用

本机已有配置沿用，不生成/重置账号或令牌：

```powershell
py -3 -X utf8 start_cloud.py --config D:\PenganLocal\cloud-config.json
# 等价
node gateway/cloud-main.mjs --config D:\PenganLocal\cloud-config.json
```

本机正式入口：http://127.0.0.1:5201/ 。使用原管理员账号登录，选择设备→图片资料→填写说明/拍摄时间→选择JPEG/PNG→确认授权→上传。网页“以演示模式浏览”只能看页面，不保存图片。5199为旧开发代理，默认上游5187，本轮正式使用5201。

实际本机数据库：D:\PenganLocal\data\database\records.sqlite；图片：D:\PenganLocal\data\database\images。不要上传部署目录/账号/令牌到源码包。

Ubuntu复用同一后端，dataDir在项目外，本地磁盘，目录700、文件600；正式浏览器需HTTPS反向代理。Windows chmod不能替代ACL核对。本轮监听127.0.0.1，没有开放局域网/公网、未部署Ubuntu。

备份首版流程：正常停止服务、确认进程退出，再整体备份dataDir（原链、数据库及images全部保留）；恢复到新的私有目录后校验启动。运行中禁止只复制records.sqlite忽略WAL；在线备份工具、自动轮转与异地恢复演练尚未实现。
