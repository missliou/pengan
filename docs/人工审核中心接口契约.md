# 人工审核中心接口契约

任务：QWEN-HUMAN-REVIEW-20261103 · 执行者：Qwen-3.8 · 日期：2026-11-03
实现位置：`gateway/human-review.mjs`（模块）、`gateway/cloud-server.mjs`（路由接线）、`admin-ui/src/pages/review.js`（前端页面）。

## 0. 定位与不重复开发的说明

本功能承接 `docs/协作记录/CLOUD-RAG-PIPELINE-20261103.md` 末尾列出的"人工复核回填仍待做"，以及 `待办.md` 中"把 needs_human 接成人工确认按钮与二次审核回填链路（当前只有提示文案）"。

**复用而非重造**：
- 队列、详情、人工意见全部**从既有持久化审计链派生**（`gateway/cloud-history.mjs` 的 `pipeline_state` 行），没有新建第二套任务存储。
- 因此**未修改** `gateway/pipeline-tasks.mjs`、`agent-pipeline.mjs`、`agent-audit.mjs`、`knowledge-store.mjs`、`cloud-history.mjs`、`cloud-security.mjs`。
- 鉴权、CSRF、Origin、设备选择与角色判定全部沿用 `cloud-server.mjs` 既有中间件；新路由写在 `requireCsrf`/`requireRole('admin')` 之后，因此权限自动生效。
- 前端复用 `PageScope`（读请求取消）、`MutationGate`（跨页面写互斥）、`api.js` 的 CSRF 头与 401 会话失效广播。

## 1. 接口清单

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | `/admin-api/review?gatewayId=&verdict=&reviewStatus=&limit=` | admin / viewer | 审核队列 |
| GET | `/admin-api/review/{taskId}?gatewayId=` | admin / viewer | 任务详情 |
| POST | `/admin-api/review/{taskId}?gatewayId=` | 仅 admin + CSRF | 提交人工意见 |

三个接口都要求管理会话 Cookie；写接口另需 `x-pengan-csrf` 与同源 `Origin`。设备身份由 `gatewayId` 决定，沿用既有 `selected()` 解析：单设备可省略，多设备必须显式指定，**不静默选第一台**。

### 1.1 GET /admin-api/review

查询参数：

| 参数 | 取值 | 默认 |
|---|---|---|
| `gatewayId` | 已登记设备 | 单设备时可省略 |
| `verdict` | `needs_human` \| `block` \| `allow` \| `all` | `needs_human` |
| `reviewStatus` | `pending` \| `reviewed` \| 省略（两者都要） | 省略 |
| `limit` | 1–200 | 50 |

非法取值一律 `400 invalid_review_query`，不做静默忽略。

响应（200）：

```json
{
  "schemaVersion": 1, "gatewayId": "dayu-a",
  "filter": {"verdict": "needs_human", "reviewStatus": null, "limit": 50},
  "counts": {"needs_human": 1, "block": 1, "allow": 0, "pending": 1, "reviewed": 0, "unfinished": 0},
  "items": [{
    "taskId": "…", "gatewayId": "dayu-a", "status": "completed",
    "verdict": "needs_human", "modelVerdict": "needs_human", "authoritative": "rules",
    "riskLevel": "high", "confidence": 0.42, "prompt": "…",
    "startedAt": 0, "finishedAt": 0, "version": 3,
    "reviewStatus": "pending", "reviewCount": 0, "humanDecision": null,
    "historical": true, "isCurrent": false, "executed": false
  }],
  "total": 1, "historical": true, "isCurrent": false, "executed": false,
  "scope": "recent-audit-window",
  "note": "队列为最近审计窗口派生视图，不是全量归档。"
}
```

要点：
- `counts` 按该设备的**完整视图**统计，不受 `verdict`/`limit` 过滤影响，因此界面可以同时显示"待审 1 · block 1"。
- `pending`/`reviewed` 只对 `needs_human` 计数：`allow` 不需要复核，不该被算进待办；`block` 只能驳回留痕，也不算待办。
- 每条任务只保留**最新快照**（同一 `taskId` 的多次 `pipeline_state` 覆盖），所以队列项数等于任务数，不等于事件数。

响应（200）在队列字段之外追加原始内容与审核记录：

```json
  "version": 3,

  "decision": {"intent": "…", "situation": "…", "confidence": 0.42, "riskLevel": "high", "openQuestions": ["…"]},
  "plan":    {"summary": "…", "steps": [{"action": "…", "reason": "…", "maxRunMs": 5000}], "evidence": []},
  "stages":  [{"stage": "decision", "state": "passed", "durationMs": 120, "summary": "…", "error": null}],
  "retrieval": {"method": "lexical", "untrusted": true, "items": [{"chunkId": "…", "documentId": "…", "title": "…", "source": "…", "content": "…", "score": 1.2, "contentSha256": "…"}]},
  "memory": {"used": 0, "sources": []},
  "traceId": "…", "provider": "deepseek", "model": "…", "calls": 3,
  "events": [{"seq": 1, "type": "task_started", "at": 0, "data": {"readOnly": true}}],
  "reviews": [{"seq": 12, "recordedAt": 0, "reviewSeq": 1, "decision": "approve", "comment": "…", "actor": "…", "version": 3, "originalVerdict": "needs_human", "fingerprint": "…"}],
  "reviewStatus": "pending", "humanDecision": null,
  "canApprove": true, "canReject": true, "blockedReason": null,
  "historical": true, "isCurrent": false,
  "executed": false, "hardwareControl": false, "deviceCommandIssued": false
}
```

- `audit`/`decision`/`plan`/`stages`/`retrieval`/`events` 是**原样透传**的模型阶段结果，人工审核不写回这些字段。
- `reviews` 是独立追加的人工意见列表，按 `reviewSeq` 升序。
- `version` 等于事件条数，是提交审核时必须回传的版本号。
- `canApprove`/`canReject` 表达"该决策当前是否有意义"（例如 block 不可通过），**不是权限位**；权限由角色与 CSRF 决定。
- `deviceCommandIssued` 恒为 `false`：本功能不存在设备控制通道。

### 1.3 POST /admin-api/review/{taskId}

请求体（严格白名单，多余字段 `400 invalid_review_body`）：

```json
{"taskId": "…", "decision": "approve | reject", "comment": "必填，1–2000 字", "version": 3}
```

`actor` 由服务端从会话取得，**客户端不能指定**（否则可伪造审核人）。

响应（200）：

```json
{
  "schemaVersion": 1, "ok": true, "duplicate": false,
  "review": {"seq": 12, "recordedAt": 0, "reviewSeq": 1, "decision": "approve", "comment": "…", "actor": "admin", "version": 3, "originalVerdict": "needs_human", "fingerprint": "…"},
  "originalVerdict": "needs_human", "finalVerdict": "needs_human",
  "modelConclusionUnchanged": true, "reviewStatus": "reviewed", "humanDecision": "approve",
  "historical": true, "isCurrent": false,
  "executed": false, "hardwareControl": false, "deviceCommandIssued": false
}
```

## 2. 错误码

| 错误码 | HTTP | 含义 |
|---|---|---|
| `invalid_review_query` | 400 | 队列筛选参数非法 |
| `invalid_review_body` | 400 | 请求体含未知字段或不是对象 |
| `invalid_review_decision` | 400 | 决策不是 `approve`/`reject` |
| `invalid_review_comment` | 400 | 意见为空、非字符串或超 2000 字 |
| `review_actor_required` | 400 | 无法确定审核人 |
| `review_task_not_found` | 400 | 任务不存在，或属于其它设备（不区分，避免泄露其它设备任务是否存在） |
| `review_stale_version` | 400 | 提交携带的版本与当前任务不一致 |
| `review_task_not_finished` | 400 | 任务未完成，不能审核 |
| `review_not_required` | 400 | 结论为 `allow`，无需人工复核 |
| `hard_rule_block_approve_denied` | 400 | 试图人工通过 `block` 任务 |
| `review_conflict` | 400 | 并发提交争用同一序号，另一方已先落盘 |
| `review_store_not_ready` | 503 | 审核视图尚未就绪 |
| `cloud_history_unavailable` / `history_write_failed` | 503 | 保留文件不可写，**审核未保存** |
| `admin_forbidden` | 403 | 角色不足（viewer 提交） |
| `csrf_required` | 403 | 缺 CSRF 头 |
| `origin_denied` | 403 | Origin 与配置不符 |
| `admin_unauthorized` | 401 | 会话缺失或已失效 |

状态码沿用 `cloud-server.mjs` 既有映射（`/unauthorized/→401`、`/forbidden|csrf|origin/→403`、其余→400），**未新增映射分支**，以免改变既有接口的行为。

## 3. 关键语义（要求逐条对应）

**要求 4：原模型结论不变，人工意见独立追加。**
人工意见写成一条新的审计行 `event='human_review_saved'`，追加在同一条哈希链保留文件里；任务的 `result.audit` 等字段一个字节都不改。同一任务可以有多条意见（不同管理员、不同时刻），最后一条决定 `humanDecision`，但历史意见逐条保留，每条记录当时的 `version` 与 `originalVerdict`。

**要求 5：硬规则 block 不可被人工"通过"覆盖。**
`verdict==='block'` 且 `decision==='approve'` → `hard_rule_block_approve_denied`，且**不落任何记录**。`block` 允许 `reject`，用于留痕确认，返回体 `finalVerdict` 仍是 `block`。前端同步禁用"通过"按钮并说明原因，避免用户点了才知道。

**要求 6：防重复提交、版本校验、会话过期与保存未确认。**
- 版本 = 任务事件条数。提交必须回传详情里读到的 `version`；不一致即 `review_stale_version`，拒绝基于过期快照的审核。
- 精确重试（同任务 + 同审核人 + 同决策 + 同意见 + 同版本）命中 `fingerprint`，返回原记录并标 `duplicate: true`，不产生第二条。
- 并发不同意见争用同一 `reviewSeq`，由哈希链的 `key` 冲突映射为 `review_conflict`，只有一条成功。
- 写盘失败（`history_write_failed` 等）如实抛错，前端显示"提交未确认"并保留已填意见，**不谎报成功**。
- 会话过期由既有 401 处理路径广播 `pengan-session-expired`，前端回登录门。

**要求 7：复用既有认证、CSRF、设备隔离与持久化审计。**
新路由位于 `security.authenticate` → `requireCsrf` → `requireRole('admin')` 之后；设备隔离复用 `selected()`；人工意见与审核动作都写进 `cloud-history.mjs` 的哈希链保留文件，因此自动继承其敏感字段名拦截（`password|token|secret|api_key|wifi_ssid` 等键名直接拒绝落盘）与重启恢复。

**要求 8：演示数据明确标注，演示模式不调用真实写接口。**
`review.js` 在 `demoMode` 下**不发起任何读请求**，渲染固定的样例详情并常驻"演示模式：不会保存任何内容"标注；提交按钮禁用。`MutationGate.run` 本身也会在演示模式抛 `demo_read_only`，构成第二道防线。

## 4. 明确的边界（不夸大）

- **不下发设备控制**：本模块没有任何控制通道，也不调用 `runtime.mjs` 的模拟接口；返回体恒 `executed:false`、`deviceCommandIssued:false`。
- **不输出模型内部思维链**：事件与阶段摘要沿用既有可解释字段。
- **队列是窗口视图**：最近 100 任务视图 / 单次最多返回 200 条，`scope:'recent-audit-window'` 已如实标注；全量归档仍由保留文件管理，服务端条件查询属后续任务。
- **人工审核不改变安全判定**：即使管理员通过，`verdict` 仍为 `needs_human`；若将来要把人工结论接到执行链路，必须另做设计并保留这条独立记录语义，不能就地改写 `audit`。
- 审核意见由人自由填写，界面提示不要写密码、密钥或家庭网络信息；但服务端只按字段名拦截，**不审查自由文本内容**。
