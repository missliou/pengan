# 多光谱监测与作物人工标记

任务 MULTISPECTRAL-20261104，执行 Codex。用户要求增加多光谱监测选项卡，并标记有问题的作物。第一版交付独立Web选项卡与持久化人工复核，不冒充尚未接入的光谱设备或AI检测。

## 当前可用

- 左侧农业助手新增“多光谱监测”，沿用现有主题与折叠菜单。显示可见光影像入口、红光/近红外未接入、NDVI不可计算。
- 只列所选设备的作物图片，20条分页；人员图片排除，不能借该接口访问或标记。
- 先在“图片资料”上传JPEG/PNG作物照片，再在新页面选择照片，填写作物位置、观察依据和结论。
- 状态：待复核、疑似异常、确认异常、本次未见异常。均为人工判断，不将“未见异常”称作自动健康诊断；异常状态必须填写观察依据。
- 用百分比X/Y/宽/高添加矩形，SVG覆盖层与原图对齐，最多10个框，可移除最后一个。此版用坐标表单添加，尚未实现鼠标拖拽或逐株分割。
- 保存时按设备和图片绑定，记录管理员、时间、版本和source=manual。追加到现有哈希审计链，同步已有SQLite历史索引，重启恢复；不改变图片原文件，不自动发给模型。
- 已保存标记显示在影像列表中。viewer只读，admin保存；CSRF、Origin与设备隔离沿用服务端会话保护。expectedRevision防覆盖他人修改，409时引导重新选择读最新记录，不自动重试覆盖。
- 保存期间锁定编辑字段；成功提示不会被随后刷新列表覆盖。

## 接口契约

- GET `/admin-api/crop-reviews?gatewayId=...`：本设备作物图片和最新人工复核，20条，nextBeforeSeq游标。
- GET同路由带mediaId：图片元数据与review；未复核revision=0、source=none。
- POST同路由：JSON `{mediaId,expectedRevision,status,plot,note,regions}`，服务端填写actor/reviewedAt/source，确认成功才返回saved:true。
- regions为百分比坐标，x/y≥0、宽高>0、边界不得超100。clear/unreviewed不能携带异常框；拒绝未知字段和客户端声称AI来源。
- 记录事件crop_review_saved，scope=crop；每次版本递增，旧记录保留。沿用原审计链64MiB上限与错误处理，不是无限保存。
- 返回multispectralConnected:false、indicesAvailable:false，仅描述本版尚无接入能力，不声称已经探测现场相机在线状态。
