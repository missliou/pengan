## 1. 要消除的依赖是什么

`规则.md` 第 3 条：正式路径不依赖网页配置，电脑只临时测试。当前实际依赖有两处，必须分别消除：

| 现有依赖 | 证据 | 消除方式 |
|---|---|---|
| 模型配置在电脑网页保存 | `GatewayLink.ets:360` 错误文案「请先在电脑网页的模型设置保存配置」；`ai_not_configured` 由网关返回 | 配置职责移到云端；原生端只做"测试连接"，不承载密钥录入 |
| 数据中转跑在电脑上 | 电脑 `gateway/` + `start_server.py` 提供 `/api/*` | DAYU200 直采（链路 A）+ 主动上报云端（链路 B） |

**关键判断：模型密钥不应该放进 HAP。** 密钥一旦进入应用包，就等于分发给每一个安装包，与"密钥保留在服务端"的红线冲突。因此本设计不把"原生配置密钥"当作目标，而是把"设备令牌配置"和"云端地址配置"作为原生配置入口的范围。

## 2. 原生配置入口（现状与最小迁移）

### 2.1 已核实基线

- `ConnectionSettings.ets:4`：`DEFAULT_GATEWAY = 'http://127.0.0.1:5187'`。
- `normalizeGatewayAddress()`（同文件 7-21 行）已实现的规则，**保留不动，直接复用为云端配置的强制校验**：
  - 只接受 `http(s)://主机[:端口]`，不含路径、账号、参数；长度 ≤ 240。
  - 主机名不得以点开头/结尾、不得含连续点；端口 1–65535。
  - 纯数字主机必须是合法 IPv4（每段 ≤255 且无前导零）。
  - **公网地址必须 HTTPS**；HTTP 只允许 `localhost` 与 RFC1918（`127/8`、`10/8`、`192.168/16`、`172.16-31`）。
- 存储：`preferences` 实例 `pengan_connection_v1`，键 `gatewayAddress`；`save()` 走 `put`+`flush`；读取失败即报「连接配置读取失败」并置空 store（不静默回落默认值）。
- 调用点：`Index.ets:105` 启动载入、`Index.ets:869` 保存、`GatewayLink.configure()` 会重置样本时间并递增 `revision`；`Index.ets:963` 切换运行/演示模式时重新 `configure` 并 `resetHardware`。**这套"配置变化即作废旧会话"的语义是对的，迁移时必须保留。**

### 2.2 目标配置分组（原生页面，非网页）

```text
组 A 局域网采集（直采板子）
  - 板子地址：IPv4 必填，强制私网校验（复用同一规则的私有网段分支）
  - 板子设备 ID：只读显示 "hh-hsp101-001"，不允许改成任意值（避免与帧校验白名单不一致）
  - 连接自检按钮 → 结果如实显示"局域网可达 / 已取到新帧 / 采样时间"
  - 明确文案：获取局域网 IP 不等于互联网可达

组 B 云端接入
  - 云端地址：强制 HTTPS（组 A 规则对公网分支已保证）
  - 设备令牌：写入后不回显、不导出、不进日志、不进报告与 ZIP
  - 连接自检按钮 → 只做 4.1 的轻量探针，不调用模型

组 C 运行状态（只读）
  - 当前模式、最近一次有效采样时间、待发队列条数、是否有丢弃
```

### 2.3 令牌录入方式待定项（需决策，不擅自定案）

| 方式 | 运维成本 | 安全 | 说明 |
|---|---|---|---|
| 云端人工建号后，用户在原生页录入令牌 | 低 | 中 | 最易实现，无需新协议；令牌需可轮换 |
| 一次性配对码（云端生成短期码，设备换取长期令牌） | 中 | 中高 | 需要云端多两个接口，但避免长期令牌明文录入 |
| 设备证书双向 TLS | 高 | 高 | 依赖证书签发链，DAYU200 上的能力与实际系统支持须先核实 |

本设计**不预设结论**。若需要尽快打通三端，第一种代价最小；若要写进答辩的"原生安全能力"证据，第三种需要额外核实设备端能力后才能承诺。

### 2.4 一个必须先核实的事实

`openharmony/entry/src/main/module.json5` 当前只声明 `ohos.permission.INTERNET` 与 `ohos.permission.CAMERA`。若原生端要显示本机 IP、或读取网络状态变化来做断网判定，可能涉及额外网络类权限。本任务**没有**擅自添加权限，因为权限声明属于共享的构建配置，且"是否需要"取决于最终接口取舍，需在实现阶段用实际 SDK 核实后再改，并在交接中列出新旧差异。

## 3. 云端接线的最小可实现顺序

为了不被"云端还没建"阻塞原生联调，建议端侧保留一个可关掉的开关：

```text
localOnly = true  → 只直采 + 本地显示 + 本地历史，不出网
localOnly = false → 直采 + 上报云端（组 B 已配置时才允许切到这个状态）
```

顺序：

1. 原生直采（链路 A）先跑通并真机验收 —— 这一步不依赖云端，收益最直接。
2. 云端做 `POST /api/v1/telemetry/batch` + 鉴权 + 追加式存储（链路 B）。
3. 把 `gateway/agent.mjs`、`hsp-telemetry.mjs`、`hardware-history.mjs` 的真实模式逻辑作为**复用对象**迁移到云端，不从零重写，减少行为漂移；迁移时 `validateHspFrame` 必须与 `docs/DAYU200遥测帧校验向量.md` 逐条对齐（尤其 §5 发现 3：范围检查只在 `*_ok` 为真时执行）。
4. 原生端"读取当前快照/最近历史"的入口从电脑网关切到云端接口；错误码文案随之更新（不再出现"电脑网页"字样）。
