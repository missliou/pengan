# Ubuntu云端Web管理平台

更新时间：2026-11-02。用户最新明确要求：提供可直接通过浏览器访问的平台，方便配置模型、查看后台记录，并提升界面质量。此要求替代之前“不再建设正式网页”的安排。本文件是可执行任务范围，当前并未实现或部署该新平台。

## 产品边界

- DAYU200：独立ArkTS/ArkUI原生HAP，现场采集、任务交互与本地状态；禁止嵌入本平台作为业务界面。
- Ubuntu：后端及独立Web管理平台，集中管理配置、设备和历史；可由电脑或手机浏览器访问，不要求浏览器持续打开才能采集。
- HH-HSP101：采集/OLED/配网及局域网遥测；仍由DAYU200转发云端，云端不直接读取家庭私网IP。
- 模型密钥只保留在服务器。浏览器录入时不回显已存明文，不进入HAP、日志或交付包。

## 页面与第一阶段功能

| 页面 | 应实现内容 |
|---|---|
| 登录与会话 | 实际管理端鉴权、退出、会话失效；管理员身份和设备接入令牌分开，不能用隐藏按钮代替鉴权 |
| 运行总览 | 设备连接状态、最后采样时间、有效/失效读数、模型配置与最近一次测试状态、存储健康；缺数据明确空态，不虚构统计 |
| 设备管理 | 设备列表、DAYU200与HH-HSP101关联、最近上报、来源、诊断；设备配对/令牌仅在相应后端实现后开放 |
| 模型配置 | 服务商、模型名、密钥保存/保留/替换/清除；手动连接测试、错误解释、图像能力标识；配置变化不能混入旧请求成功提示 |
| 真实采集记录 | 时间/设备筛选、分页、质量标记、来源与采样/接收时间；当前与历史分开，支持明确范围的导出 |
| AI分析与任务 | 问题、任务步骤、真实工具调用、模型、依据时间、记忆来源与持久化结果；不把“模型建议”显示成“硬件执行成功” |
| 系统与审计 | 后端/存储状态、配置变更和登录等管理事件、错误诊断；日志脱敏，无自动清空历史或一键危险操作 |

趋势图只绘制实际有效数据，缺口保持缺口；没有CO/CO₂就显示未接入。模型“已保存”“上次测试通过”和“当前可用”是不同状态。第一阶段不做未经授权的自动控制，不自动上传照片。

## 界面方向

专业管理控制台：清晰侧栏、统一间距和字号、表格筛选与分页、状态标记、趋势图、空态/加载/失败/保存反馈。桌面方便管理，手机浏览器可用。避免用大幅宣传区和虚构指标营造完成感；优先让真实数据与操作状态一眼可辨。

## 验收清单

- 登录后可真实保存模型配置，刷新/重启后仍保留；响应不含已存明文密钥。
- 未登录请求不能读取敏感配置、修改模型或管理设备；退出后失去权限。
- 手动模型测试失败不会展示旧成功结果，测试不发送现场数据或照片。
- 设备离线/数据过期后清除当前正常状态，历史仍可查询；筛选和导出范围明确。
- 日志与导出不含密钥、令牌、家庭密码或未经允许的照片内容。
- 真正通过DAYU200向云端上报后，原生端与Web查看的是同一数据来源；浏览器关闭后上报不停止。
