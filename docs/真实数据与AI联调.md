# 真实数据与 AI 联调

2026-10-31：默认启动已改为真实数据运行模式。原生应用、电脑控制台与服务端都不再将模拟数值作为默认现场读数。

## 启动

```powershell
node tools/system.mjs --host 192.168.1.89
```

连接HH-HSP101后，确认它在设备管理器中的实际串口，再添加 `--serial COM7`。采集器断线后仅重试该端口，不扫描其他设备。未连接时显示未知；不会启动虚拟设备补充读数。DAYU200诊断页保存电脑的实际局域网地址。默认只读采集，无执行器控制。

软件演示必须显式启动：

```powershell
node tools/system.mjs --host 127.0.0.1 --mode simulation
```

网页无法切换服务端运行模式。真实模式返回403拒绝模拟设备、模拟命令、模拟场景和模拟计划接口；原生演示入口不能绕过服务端限制。

## 真实采集与历史

- `GET /api/health`：运行模式及真实采集连接状态。
- `GET /api/observations`：真实只读快照、能力清单与未知准入状态。
- `GET /api/hardware`：HH-HSP101独立采集接口，保留供原生轮询。
- `GET /api/hardware/history?limit=50`：最近真实记录，明确 `historical=true`、`isCurrent=false`。
- `GET /api/agent/history?limit=20`：最近真实文字AI分析，包含问题、模型、原采集依据与只读工具溯源，同样明确为历史。
- `GET /api/reports/latest`：导出最近50条采集、20条文字分析和导出时刻的当前快照。JSON声明不是完整历史，离线不以历史补值，超过1MiB明确拒绝。网页点击下载；原生台账调用系统文件选择器保存，取消或上下文变化不报成功。不导出照片或配置，不触发模型。

数据来源是串口接收器写入的 `tmp/runtime/hsp-latest.json`。温湿度来自AHT20；MQ-2只提供原始ADC和电压，没有气体浓度标定。CO/CO₂缺失，不用土壤、光照或其他模拟值补齐。

有效新样本每2秒检查并存入 `tmp/runtime/hardware-history.jsonl`，接收时间去重，重启校验哈希链。采样过期、未来时间、非法或模拟帧不保存。文件上限64MB；达到上限停止记录并显示存储异常，不覆盖旧数据。网页与原生显示最近记录；查询窗口保留最近500条，磁盘记录仍保留。历史记录不能用于证明当前在线或准入安全。哈希链用于本地完整性检查，不是独立第三方存证。

## 使用真实模型

浏览器打开电脑服务的“模型设置”，选择DeepSeek或通义千问，填写账户可用且支持工具调用的模型名称和API密钥，再保存。千问北京工作空间账户可按控制台填写workspaceId；旧兼容账户可留空。密钥不回显；不要将密钥填入聊天或原生应用。保存后即时生效，无需重启服务。

保存后可点击“发送测试问题”（原生诊断页也有此入口）。仅此点击触发 `POST /api/agent/test {}`，验证合成问题的工具调用，不发送现场采集、历史或照片，也不保存为真实分析。测试与配置、其他AI请求互斥；成功只表示该时刻的单次测试通过，配置更新后回到未测试状态。未配置、认证/权限、限流和格式失败都有明确提示。本轮没有实际执行外部模型测试。

原生智能助手与网页真实模式调用 `POST /api/agent/analyze`。请求包含用户问题和真实只读观测；设备离线时发送明确缺失状态，模型可以分析接入问题，不能推测正常读数。真实模型未配置时返回 `ai_not_configured`，不会使用脚本伪装回答。

模型分析结果包含来源时间、发现、未知项和只读工具溯源。模型推断不是传感器测量；分析期间样本过期时，当前状态转为未知，原始快照仅保留为分析依据。所有分析均 `executed=false`、`hardwareControl=false`、`steps=[]`，不会声称风机、门禁已动作。

成功文字分析保存到 `tmp/runtime/ai-analysis-history.jsonl`。接口会单列 `persistence.saved`：模型成功但存储失败时仍显示分析结果，同时明确未保存。失败调用、模拟计划、照片与照片分析不进入该历史。记录白名单剔除附加凭据、原图、路径及内部思考字段；文件上限16MB，达到上限或发现运行中截断/删除后停止追加，保留文件与异常状态。重启校验失败时服务仍可分析，但不会覆盖损坏记录。

重启或模型配置更新后，仅从健康历史中恢复相同服务商、相同模型的最近8条文字建议；历史不代表当前观测，不恢复任何执行权。不会自动把另一服务商的历史作为新模型上下文。

用户已明确授权：真实温湿度、ADC、电压、采样时间和分析问题可发送给DeepSeek；照片仍仅用户主动点击。该授权不能作为自动向其他服务商发送数据的依据。设备与密钥由用户稍后准备，不反复要求现在接板。

## 文件位置与就绪诊断

打包后运行 `node tools/verify-release.mjs`、`node tools/list-deliverables.mjs`，生成 `output/交付文件位置.md` 和机器可读清单。总表核对HAP/ZIP/固件及已生成报告/诊断文件的实际大小和哈希；源码、清单或交付校验过期会拒绝生成。

`pwsh -NoProfile -File tools/diagnose-pengan.ps1 -ServerAddress http://192.168.1.89:5187` 只读检查本机服务、端口设备和有界HDC版本信息，输出到 `output/diagnostics`；不打开串口、不调用模型、不保存设备ID/UDID或密钥。它不证明候选已安装，也不改变驱动、信任或服务配置。

## 验收边界

代码测试中的模型响应是明确注入的测试桩；不能当作真实服务商调用证据。当前设备与密钥是否就绪，以实时接口及开发板读取为准。新版HAP编译成功也不等于已装机；实际连接后仍需安装、核对720×1280与系统栏、真实读数、失联恢复、模型实际响应。

作物巡查已实现本地拍照后主动发送给已配置模型分析，网页也支持主动选择单张照片。接口为 `POST /api/agent/inspect-image`，仅JPEG/PNG、最多2MiB；不会自动上传、在电脑服务落盘或记入日志。返回实际图像字节的SHA256、模型、时间和待复核项，不把建议当作病害确诊或准入结论。需要用户选择支持图片输入的模型并完成真实调用验证；目前代码测试不能代替这项验收。CO/CO₂传感器和执行器未接入。
