# 断网补发、设备凭据保护与语音输入

本轮完成代码、主机回归、官方 SDK HAP 构建；未签名、未装机、未做两块板实物验收。正式架构仍为 HH-HSP101 → DAYU200 原生应用 → Ubuntu。独立 Web 管理平台不嵌入 HAP。

## 断网补发

- `OfflineQueue.ets` 使用应用私有 Preferences 保存采集帧，先 flush 再发网络，收到确认后移除；重启恢复，写入失败停止修改，不静默丢弃旧记录。
- 最多 500 条、JSON 字符数上限 1048576；按 HTTPS 服务地址和 gatewayId 隔离，单批 10 条。无令牌、照片或音频入队。
- 首页/设备诊断前台采集与助手手动采样接入队列；配置完成且前台采集时每 10 秒尝试补发，诊断页也有手动按钮。不是后台常驻采集服务。
- POST `/api/v1/telemetry/replay` 使用设备认证，服务端单批上限 20 条，采集时间最多回溯 7 天，校验帧、时间与身份。与实时上传共用幂等键，冲突拒绝，重试不重复入库。
- 补发只进入历史，不更新当前采集入口，不触发设备控制或自动 AI。Web 数据记录/CSV 与原生历史显示“历史补发”。
- 队列满、损坏、超时钟范围或超过服务端 7 天窗口时显示错误；当前没有自动清理/导出/隔离坏记录，最旧不合法记录可能阻塞当前批次，需后续管理流程。没有用清空队列来掩盖失败。

## 设备凭据

- `CredentialVault.ets` 使用 HUKS AES-256-GCM，随机 12 字节 nonce，服务地址/设备身份绑定为 AAD。Preferences 仅保存密文信封，令牌运行时在内存中使用。
- 诊断页提供手动保存、恢复、忘记密文；不自动恢复，不显示令牌。缺密钥或认证失败不重新生成密钥解密、不降级明文。
- 忘记仅移除应用保存的密文，不承诺物理介质取证擦除。队列中不保存凭据。
- 主机测试使用真实 AES-GCM 运算模拟 HUKS，覆盖篡改、上下文错配、密钥丢失、存储恢复；不能代替 DAYU200 HUKS 实测。需真机验证密钥持久化和卸载行为。

## 原生语音

- `NativeSpeechInput.ets` 使用原生 audioCapturer 和运行时 MICROPHONE 权限，按钮录制最多 8 秒，PCM16LE/16kHz/单声道，在内存生成 WAV，不创建录音文件。
- 录音前先查识别服务就绪状态；支持取消、离页取消、停止/释放麦克风与过期结果丢弃。
- 设备接口 GET `/api/v1/device/speech/status`、POST `/api/v1/device/speech`，均使用设备认证。服务端只向已配置的本机回环 `/inference` 转发，禁止外部模型地址；限制 WAV 结构、大小、时长、返回长度、30 秒超时、并发识别占用。
- `gateway/speech.mjs` 不保存音频和识别正文到审计；只记录请求事件。识别结果必须带 `requiresConfirmation:true`、`executed:false`，仅填输入框，需用户检查后发送；超长输入会提示截断。
- 本机已安装校验过哈希的 whisper.cpp b5454 CPU 运行时与多语 base 模型，使用固定农业词汇提示。合成中文音频经过真实设备认证 HTTP → 本地 ASR 验证成功，但“湿度”仍识别成“诗度”，准确率不算通过。未用真实人员录音，未测板载麦克风。
- 音频只送自有识别服务；本轮未将录音发给 DeepSeek。输入文字经用户确认后才进入既有助手流程。

## 本机启动

先启动识别器：

```powershell
py -3 -X utf8 start_speech.py --binary D:\PenganLocal\asr\whisper-b5454\Release\whisper-server.exe --model D:\PenganLocal\asr\whisper-b5454\ggml-base.bin
py -3 -X utf8 start_cloud.py --config D:\PenganLocal\cloud-config.json
```

ASR 仅监听 127.0.0.1:8178；服务配置新增 speechUrl 指向其 `/inference`。私有配置和备份均留在 D:/PenganLocal，不进入源码包。现有用户、模型、设备登记和数据库未重置。Ubuntu 需另备 Linux 识别器并部署 TLS；本机 HTTP 5201 可用不代表 DAYU200 HTTPS 已验收。
