# 云端运行与本机测试

本轮已实现服务、原生上传和独立Web，主机集成/浏览器验证通过；尚未实测Ubuntu部署、真实TLS或两块板。HAP依旧未签名。本说明不是已上线凭据。

## 初始化与启动

尚无Ubuntu时可先用Windows持久本机管理入口：`py -3 setup_cloud.py D:\PenganLocal --local`，随后`node gateway/cloud-main.mjs --config D:\PenganLocal\cloud-config.json`，浏览器访问http://127.0.0.1:5201。初始化由操作人员设置真实密码，不预设默认管理员；目录必须在源码之外。此模式只提供本机Web管理/持久存储测试，原生设备令牌仍强制HTTPS，不会借本机模式放宽令牌传输。连接实板前另准备可信HTTPS。

Node22+、Python3.9+。在源码目录运行，部署配置目录必须在源码之外：

```text
python setup_cloud.py /etc/pengan
node gateway/cloud-main.mjs --config /etc/pengan/cloud-config.json
```

Windows同样可用，例如`py -3 setup_cloud.py D:\PenganDeploy`和`node gateway/cloud-main.mjs --config D:\PenganDeploy\cloud-config.json`；旧start_server.py仍保留，属于旧电脑临时网关，不是这个认证云服务。

初始化交互输入HTTPS源站、管理员名、DAYU200登记ID和两次不回显密码，生成scrypt摘要及设备随机凭据；不覆盖已存在文件，不打印密码/令牌。cloud-config.json供服务器读取，device-credential.json只供本机录入开发板。不要发到聊天/日志/源码包。Windows文件mode不能代替ACL，需要操作人员核对；Linux目录/文件权限为700/600，服务用户需能读取配置、写dataDir。测试过Python生成摘要与Node登录兼容，未初始化真实部署账号。

配置的users数组可登记admin/viewer两类账号（每人独立密码摘要），devices数组按gatewayId登记tokenSha256。不要复制他人密码摘要充当新账号。当前配置更新/禁用账号、设备凭据轮换通过受控部署文件与服务重启完成，没有自助注册/在线用户管理页面。重启使管理会话失效；设备令牌不是管理员密码，不能访问管理API。

dataDir默认在配置目录下，可改为持久盘绝对路径，例如/var/lib/pengan；勿放项目tmp。目录包含历史JSONL、按登记设备分区的最新观测、服务端模型配置和cloud-writer.lock。配置和模型密钥文件权限受限，不声称已经文件内容加密。只允许一个进程写同一dataDir；异常退出留下锁时，必须先确认旧服务确实停止，再由操作人员检查处理锁，程序不会自动抢锁。备份应在停服后完整复制dataDir；不要只恢复最新帧而遗漏历史/会话去重状态。

## HTTPS反向代理

服务固定监听127.0.0.1:5201（配置port可改）。生产publicOrigin必须等于浏览器使用的HTTPS源站，包含非默认端口，不含路径。反代保持Origin和Cookie，不能关闭TLS校验。nginx参考（证书实际路径由部署者配置）：

```nginx
server {
    listen 443 ssl;
    server_name pengan.example.com;
    ssl_certificate /etc/letsencrypt/live/pengan.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/pengan.example.com/privkey.pem;
    client_max_body_size 3m;
    location / {
        proxy_pass http://127.0.0.1:5201;
        proxy_set_header Host $host;
        proxy_set_header Origin $http_origin;
        proxy_read_timeout 40s;
    }
}
```

前端dist由服务端同源提供；更新admin-ui后先node admin-ui/build.mjs。不要另外把未认证旧gateway端口反代到公网。本轮未配置真实域名/证书/firewall/systemd，以上模板未在Ubuntu验收。

## 原生与数据流

DAYU200设备诊断保存服务端HTTPS地址，选择采集板直连、保存真实私网IP；录入部署登记ID和设备令牌，启用设备云会话。令牌仅进程内存，输入框会清空，重启需重新录入，尚未用HUKS长期绑定。每份新鲜帧只尝试上传一次；断网/失败明确未确认，不自动补发，不宣称离线期间历史完整。云端校时窗口要求设备与服务器UTC同步。

环境AI使用同一登记设备的云端观测，核对本地会话；不同设备/会话/模型不共享记忆。设备照片分析与合成测试已走认证设备端点，照片不自动进入历史。模型在管理员Web中保存；viewer只读、不可保存或测试。此处“AI已接线”不等于真实DeepSeek已经验证。

## 历史、审计与限制

采集/文字AI/审计记录在一个持久哈希链文件内，按设备和kind分页，fsync后确认；默认64MiB上限，不静默删除老记录，满额或损坏拒绝写入。UI可游标加载更早，浏览器最多5000条，CSV只含已加载筛选窗口。后端仍能分页读取保留文件全部记录，没有将最近200条冒充完整历史。

哈希链可检测内部破坏和半行，不能仅凭同一文件证明未被整行截尾，externalCompletenessVerified恒false。生产仍需独立备份/外部检查点；目前没有自动归档轮转、无限存储或全范围服务端导出。审计保存登录/退出/权限拒绝/模型配置与调用请求等事件，不保存密码、令牌、照片正文和配置正文。
