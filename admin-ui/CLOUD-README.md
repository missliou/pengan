# 云端管理平台当前用法

默认必须通过真实/admin-api/session/login登录，不再以前端门槛代替鉴权。部署账号由服务器配置，前端不创建默认管理员。会话Cookie由后端HttpOnly管理；CSRF仅内存，不持久化密码、令牌或模型密钥。服务端401会清理真实页面上下文并返回登录；退出失败明确提示结果未确认。viewer仅浏览，保存/清密钥/模型测试在按钮及数据源两层阻断，后端仍必须实施权限校验。

演示模式是明确标注的样例且不读写真实配置；显式env.ALLOW_LOCAL_DEBUG=true才开放旧电脑调试门槛，此开关不授予服务器权限。默认值false，正式部署不能开启。

登录后读取登记设备列表，顶部选择gatewayId，观测和历史请求绑定该作用域。切设备/页面/演示保留现有取消、写互斥及10秒老化保护。设备页显示服务端登记列表；系统页读取最近50条审计的seq/recordedAt/data.event，不回显配置正文。

采集与AI历史使用nextBeforeSeq游标“加载更早记录”；筛选和CSV只针对已加载数据。每次最多200条、浏览器最多保留5000条，达到上限明确显示还有更早，不影响后端完整历史。游标/重复序号异常拒绝，已离开页面的迟到请求不追加记录。

Windows测试入口仍是node serve.mjs --upstream http://127.0.0.1:端口；/api和/admin-api都代理真实后端，校验浏览器Origin与Host同源后再翻译为上游Origin，透传Cookie/Set-Cookie/CSRF，不再把/admin-api固定返回501。正式生产用同源HTTPS反代；未启动管理服务时登录失败，不降级为本机门槛。

验证：npm test（50项）；node build.mjs（dist生产静态产物）。浏览器集成验收由协调者执行；单测包含最小DOM主机，不能替代浏览器布局/真实账号/Ubuntu部署验收。
